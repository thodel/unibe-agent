Einen KI-Agenten auf dem eigenen Computer einrichten

Diese Anleitung zeigt Schritt für Schritt, wie du OpenHands – einen KI-Agenten, der Dateien lesen, Code schreiben und Befehle ausführen kann – auf deinem Computer startest. Das Sprachmodell dahinter ist Qwen 3.8, das auf den Servern der Universität Bern (GPUStack) läuft. Deine Texte gehen also nicht an einen kommerziellen Anbieter.

1Wie das Ganze zusammenhängt

Es gibt drei Teile. Du musst nicht verstehen, wie sie intern funktionieren – aber es hilft zu wissen, welcher Teil wo läuft:

  • OpenHands läuft in einem abgeschotteten „Container“ auf deinem Computer. Du bedienst ihn im Browser.
  • Der Ordner projekte ist das Einzige, was der Agent von deinem Computer sieht. Alles andere bleibt für ihn unsichtbar.
  • Das Sprachmodell („das Gehirn“) läuft auf dem GPUStack-Server der Uni. Den erreichst du nur aus dem Uni-Netz oder über VPN.

2Was du brauchst

  • Einen Campus-Account der Universität Bern
  • Zugang zu GPUStack (gpustack.unibe.ch) mit Berechtigung für das Modell qwen3.8-27b
  • Einen Computer mit macOS, Windows 10/11 oder Linux, mindestens 8 GB Arbeitsspeicher und rund 5 GB freiem Speicherplatz
  • Etwa 30–45 Minuten Zeit beim ersten Mal

Du brauchst keine Programmierkenntnisse. An zwei Stellen tippst du einen Befehl in ein „Terminal“ – das wird jeweils genau erklärt.

3Mit dem Uni-Netz verbinden (VPN)

GPUStack ist nur innerhalb des Uni-Netzes erreichbar. Wenn du nicht im Uni-WLAN sitzt, verbinde dich zuerst mit dem VPN der Universität.

  1. Installiere den VPN-Client nach der offiziellen Anleitung der Uni: VPN-Client herunterladen, installieren und konfigurieren (Serviceportal). Übersicht: Zugang auf interne Ressourcen mit VPN.
  2. Melde dich mit deinem Campus-Account an.
  3. Lass das VPN verbunden, solange du mit dem Agenten arbeitest.
Merksatz

Ohne VPN lässt sich OpenHands zwar öffnen, aber der Agent antwortet nicht – ihm fehlt dann das Sprachmodell.

4Docker installieren

Docker ist ein Programm, das andere Programme in abgeschotteten „Containern“ laufen lässt. So musst du OpenHands nicht selbst installieren, und es kann nichts ausserhalb seines Ordners verändern.

  1. Lade Docker Desktop für dein Betriebssystem herunter und installiere es.
    • Mac: Wähle die Version für deinen Prozessor (Apple-Chip M1/M2/M3/M4 oder Intel; unter › „Über diesen Mac“ nachsehen). Alternativ funktioniert auch OrbStack.
    • Windows: Das Installationsprogramm richtet bei Bedarf „WSL 2“ ein und verlangt danach einen Neustart.
  2. Starte Docker Desktop einmal und warte, bis unten links „Engine running“ steht. Ein Docker-Konto brauchst du nicht – die Anmeldung kannst du überspringen.

Ein Terminal öffnen

Für die nächsten Schritte brauchst du ein Terminal – ein Fenster, in das du Befehle tippst:

  • Mac: ⌘+Leertaste, „Terminal“ eintippen, Enter.
  • Windows: Startmenü öffnen, „PowerShell“ eintippen, Enter.

Prüfe, ob Docker läuft. Tippe diesen Befehl ein und drücke Enter:

docker version

Wenn mehrere Zeilen mit „Client“ und „Server“ erscheinen, ist alles bereit. Erscheint eine Fehlermeldung, ist Docker Desktop noch nicht gestartet.

5Einen API-Schlüssel bei GPUStack holen

Ein API-Schlüssel ist wie ein Passwort für Programme: Damit weist sich OpenHands bei GPUStack aus.

  1. Öffne gpustack.unibe.ch (VPN muss verbunden sein) und klicke auf Log in with SSO.
  2. Melde dich mit deinem Campus-Account an (dieselbe Anmeldung wie bei Outlook oder ILIAS).
  3. Klicke oben rechts auf das Personen-Symbol und dann auf API Keys.
  4. Klicke auf + Add API Key.
  5. Fülle das Formular aus:
    • Name: etwas, woran du den Schlüssel wiedererkennst, z. B. openhands
    • Expiration: wie lange der Schlüssel gilt. „1 month“ ist ein guter Anfang; danach legst du einfach einen neuen an.
    • Model Access: Allowed models wählen und das Häkchen bei qwen3.8-27b setzen. So kann der Schlüssel nur dieses Modell benutzen.
  6. Klicke auf Save. GPUStack zeigt dir jetzt den Schlüssel an. Kopiere ihn sofort – er wird nur dieses eine Mal angezeigt. Es dauert etwa eine Minute, bis er funktioniert.
Den Schlüssel geheim halten

Der Schlüssel wird nur einmal angezeigt. Kopiere ihn sofort in deinen Passwortmanager oder eine Notiz, die nur du siehst. Schick ihn nie per Mail oder Chat und lade ihn nie auf GitHub hoch. Wenn er doch in falsche Hände gerät: in GPUStack löschen und einen neuen anlegen.

6Den Arbeitsordner vorbereiten

Lege einen Ordner unibe-agent an und darin einen Unterordner projekte. In projekte legst du später alles, woran der Agent arbeiten soll.

Mac (im Terminal):

mkdir -p ~/unibe-agent/projekte
cd ~/unibe-agent
curl -fsSLO https://thodel.github.io/unibe-agent/compose.yaml

Windows (in PowerShell):

mkdir $HOME\unibe-agent\projekte
cd $HOME\unibe-agent
curl.exe -fsSLO https://thodel.github.io/unibe-agent/compose.yaml

Der letzte Befehl lädt die Datei compose.yaml herunter. Sie sagt Docker, welches Programm es starten soll und welchen Ordner es sehen darf. Du musst sie nicht verändern.

Tipp: nur Kopien hineinlegen

Der Agent darf im Ordner projekte Dateien ändern und löschen. Lege dort für den Anfang Kopien ab, nicht deine einzigen Originale.

7Den Agenten starten

Bleib im selben Terminal-Fenster (im Ordner unibe-agent) und tippe:

docker compose up -d

Beim ersten Mal lädt Docker das Programm herunter (rund 2 GB, je nach Verbindung einige Minuten). Danach öffne im Browser:

http://localhost:8031/canvas

„localhost“ heisst: Die Seite kommt von deinem eigenen Computer, nicht aus dem Internet. Niemand sonst kann darauf zugreifen. Die Zahl 8031 ist der „Port“ – eine Art Hausnummer auf deinem Computer.

Tipp: Lege dir für diese Adresse ein Lesezeichen an.

Gelbe Leiste „Your LLM isn't set up yet“?

Dann fehlt der API-Schlüssel. Klicke auf Set up LLM und trage ihn nach. Hast du mehrere Profile angelegt, wähl unter dem Eingabefeld (beim Modellnamen) das Profil mit Schlüssel aus.

9Den Projektordner freigeben

Damit der Agent mit deinen Dateien arbeiten kann, wählst du den Ordner projekte als „Workspace“:

  1. Klicke unter dem Eingabefeld auf Open Workspace, dann im Auswahlfeld auf + Add Workspace.
  2. Klicke links auf /projects (so heisst dein Ordner projekte im Container) und dann auf Add this directory.
  3. Klicke auf Confirm. Unter dem Eingabefeld steht jetzt projects.

10Die erste Aufgabe

Tippe eine Aufgabe ins Eingabefeld und drücke Enter. Für den Anfang eignet sich etwas Harmloses:

Liste alle Dateien im Workspace auf und beschreibe in drei Sätzen, worum es darin geht.

Der Agent zeigt dir jeden Schritt: welche Befehle er ausführt, welche Dateien er liest und was er ändert. Lies mit, besonders am Anfang.

Gute Aufgaben für den Einstieg

  • „Wandle alle Word-Dateien in briefe/ in reinen Text um.“
  • „Zähle in transkription.txt, wie oft jeder Ortsname vorkommt, und speichere das Ergebnis als CSV.“
  • „Schreib einen Einladungsbrief als Word-Datei an …“ – siehe das Beispiel unten.
  • „Schreib ein kleines Python-Skript, das alle Dateinamen in scans/ nach dem Muster Jahr_Nummer umbenennt – führ es aber erst aus, wenn ich zustimme.“
Gut zu wissen

Qwen 3.8 ist ein „denkendes“ Modell: Vor der eigentlichen Antwort überlegt es oft eine Weile. Das ist normal. Es arbeitet langsamer als kommerzielle Dienste und macht Fehler – prüfe die Ergebnisse, bevor du dich darauf verlässt.

11Stoppen, starten, aktualisieren

Alle Befehle tippst du im Terminal im Ordner unibe-agent (vorher cd ~/unibe-agent, unter Windows cd $HOME\unibe-agent).

WasBefehl
Agent stoppendocker compose down
Agent wieder startendocker compose up -d
Läuft er?docker compose ps
Was ist passiert? (Protokoll)docker compose logs --tail 50

Solange Docker Desktop läuft, startet der Agent nach einem Neustart des Computers von selbst. Deine Einstellungen und Gespräche liegen im Ordner openhands-daten und bleiben beim Stoppen erhalten.

Aktualisieren: Lade die neueste compose.yaml erneut herunter (Befehl aus Schritt 6) und starte dann mit docker compose up -d. Docker holt die neue Version selbst.

Ganz entfernen: docker compose down, dann den Ordner unibe-agent löschen. Den API-Schlüssel in GPUStack ebenfalls löschen.

12Wenn etwas nicht klappt

Was du siehstWas es bedeutet und was hilft
„Api key not allowed to access model qwen3.8-27b“Der Schlüssel darf dieses Modell nicht verwenden. In GPUStack einen Schlüssel anlegen, bei dem qwen3.8-27b erlaubt ist (Schritt 5).
„Connection error“, „timed out“ oder der Agent antwortet nichtVPN prüfen. GPUStack ist nur im Uni-Netz erreichbar.
Die Seite localhost:8031 lädt nichtLäuft Docker Desktop? Dann docker compose up -d im Ordner unibe-agent.
„port is already allocated“Ein anderes Programm belegt Port 8031. In compose.yaml die Zeile "127.0.0.1:8031:8000" zu "127.0.0.1:8032:8000" ändern, docker compose up -d ausführen und localhost:8032/canvas öffnen.
Der Agent sieht meine Dateien nichtLiegen sie im Ordner unibe-agent/projekte? Ist der Workspace projects gewählt (Schritt 9)?
„Your LLM API key appears to be invalid“ oder gelbe Leiste „Your LLM isn't set up yet“Das gewählte Profil hat keinen oder einen falschen Schlüssel. Unter dem Eingabefeld das richtige Profil wählen oder über Set up LLM den Schlüssel nachtragen.
In projekte taucht ein versteckter Ordner .git aufDas legt OpenHands selbst an, um Änderungen nachverfolgen zu können. Einfach liegen lassen. Darum auch nie den ganzen Benutzerordner freigeben, sondern nur projekte.
Die Antwort bricht mitten im Satz abDas Modell hat sein Längenlimit erreicht. Die Aufgabe in kleinere Teile zerlegen.
